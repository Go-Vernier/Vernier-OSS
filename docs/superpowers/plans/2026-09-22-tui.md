# The TUI — implementation plan

Spec: `docs/superpowers/specs/2026-09-22-tui-design.md`. Branch: `tui`.

1. **Engine.** Make `report::hop_words` public and re-export it. No
   behaviour change; the existing tests stay green.
2. **Crate.** `crates/vernier-tui` with ratatui 0.30 (its crossterm 0.29
   re-export) as a workspace dependency. `lib.rs` exposes `Options` and `run`.
3. **State.** `app.rs`: `App`, `Tab`, `Focus`, and `update(&mut App, KeyEvent)
   -> Action`, covering tabs, selection, filters, the back stack, depth,
   the prompt, and service or change to blast. Unit tests drive key
   sequences over `edges-http-app`.
4. **Drawing.** `ui/`: the header, then the tabs Overview, Services,
   Changes and Blast, the prompt, and help. `theme.rs` holds the colours:
   the HTML palette, the 16-colour fallback, and `NO_COLOR`.
5. **Loop.** `run`: `ratatui::init`, then draw and read events until
   `Action::Quit`, then `ratatui::restore`.
6. **CLI.** A `Tui` subcommand shares the runtime and change flags with
   `Analyze` through a flattened `clap::Args` struct. It refuses to start
   when stdout is not a terminal.
7. **Tests.** Snapshot tests of each tab on `TestBackend` at 100×30, where
   `UPDATE_SNAPSHOTS=1` rewrites the snapshots. A render pass over the
   corpus at 80×24 and 120×40. A CLI test for the not-a-terminal error.
8. **Docs.** A README section, and the spec's decisions made while building.

Checked after every step: `cargo fmt`, `cargo clippy --all-targets`, and
`cargo test`.
